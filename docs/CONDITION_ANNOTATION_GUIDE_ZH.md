# 难负例复核说明

本轮挖掘的部分“负例”可能只是没有被原数据标注的合理答案。公共模型分数只能
用来降低训练惩罚，不能代替人工正确性标签。因此另保留一个训练数据复核队列：
`reports/condition_v1/label_review/blind_queue.jsonl`，含 20 道保险 FAQ、
20 道政府问答和 10 道通用问题。当前人工完成数为 **0**；这 50 道题没有新增标签，
也没有被当作额外数据再次计数或加入本轮模型。

复核时每题展示顺序打乱的两个候选段落，不展示模型分数和原作者标签。
`mapping_do_not_show_reviewer.jsonl` 只供复核后的合并和溯源使用。
队列只取训练题，不包含独立验证或测试题。

逐条判断“这个段落是否直接回答此问题”，并记录可核对的理由：

- `directly_answers`：主体、产品/计划类型、资格条件、时间范围均匹配，段落直接支持答案。
- `partially_answers`：有相关信息，但缺少关键条件、例外、对象或时间限定。
- `wrong_scope_or_condition`：主题相近，却是不同人群、州、计划、阶段或覆盖范围。
- `insufficient_context`：缺少原文上下文或有效日期，无法判断。
- `uncertain`：存在歧义，需第二位复核者或进一步材料。

两段可以同时相关，也可以同时不足。不要因为原数据只有一个正例就强行二选一。
对于政府资料，按其原始发布日期和问题范围判断支持关系，不把历史规定当作当前建议。
如果裁定依赖来源文档中的补充内容，应写明具体 URL、段落及条件。

真正使用复核结果前，需要保存复核者、日期、理由和分歧处理记录，生成新的数据版本，
再次检查来源隔离，再训练和评估。当前队列不会自动修改已有标签、模型选择或测试指标。

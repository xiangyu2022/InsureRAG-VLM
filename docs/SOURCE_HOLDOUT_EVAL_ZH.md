## 检索结果与预算

原始 BGE 文档向量；原始/适配查询向量混合 alpha=0.5；dense top100 与正 BM25 top100 并集，最多重排 200 条；lexical weight=0.2；输出 10 条，打包前 5 条；上下文 8,000 字符、单页上限 2,400 字符。baseline cross weight=0.5。

下表均为**发布方等权宏平均**，不是按题均值。

| 划分/臂 | 完整答案保留@5 | Recall@10 | Hit@10 | nDCG@10 |
|---|---:|---:|---:|---:|
| dev baseline | 72.96% | 75.19% | 75.19% | 0.6609 |
| dev cross_only（weight=1.0） | 53.89% | 62.13% | 63.98% | 0.4969 |
| dev original_query（alpha=0） | 72.96% | 75.19% | 75.19% | 0.6502 |
| dev cross_quarter（weight=0.25） | 78.24% | 80.46% | 80.46% | 0.7317 |
| test baseline | 44.29% | 54.76% | 54.76% | 0.3801 |
| test cross_quarter | 49.76% | 58.57% | 58.57% | 0.4391 |

Recall 按每题找回 gold 数/gold 总数计算，再按题/发布方聚合；Hit 是是否至少命中一个。@10 要求至少 10 个唯一排名结果。完整答案保留要求所有 gold 片段均完整进入打包上下文。单独报告检索缺失与打包损失。

dev baseline 完整保留 **36/47**，候选 **38/47**；差值发布方聚类 CI **[0, +12.5] pp**。test 两臂均 **20/37**：CCPC **18/30→17/30**，FSRA **2/7→3/7**。test 按题 Recall@10 反而 **23/37→22/37**。小来源被等权放大，必须同时看发布方与按题口径。

baseline dev 11/47 题在检索阶段已缺完整 gold，打包导致的完整证据丢失为 0；test 两臂均 17/37 检索不完整，打包损失为 0。本轮没有证据支持把主要问题归为上下文裁剪。

cross_quarter 开发筛选复用了相同候选与分数，随后做独立推理核对：47/47 排名和打包上下文完全一致。独立 P95 检索耗时 **0.1888 秒**，baseline **0.1893 秒**；缓存重排的继承计时不用于此比较。test P95 两臂约 **0.1848/0.1847 秒**。这些时间不含模型/索引初始化，只含逐题排序、打分、打包及摊销的查询编码，不能称生产延迟。

完整指标、分组数、哈希和 2,000 次/seed=42 的成对发布方聚类 CI 见 [dev](../reports/source_holdout_v1/dev_comparison.json) 与 [test](../reports/source_holdout_v1/test_comparison.json)。只有两个 test 集群，CI 很不稳定，且跨零。

## 原始输出、最终输出与语义失败

固定未适配 Qwen3.5:4b Q4_K_M，模型 digest `2a654d98e6fba55d452b7043684e9b57a947e393bbffa62485a7aac05ee4eefd`；temperature=0、seed=42、num_ctx=4096、num_predict=384、think=false。每题有正常检索上下文和配对空上下文，各运行一次；共 **336 次生成**，无错误、截断或数字修复。

| 指标 | dev baseline | dev candidate | test baseline | test candidate |
|---|---:|---:|---:|---:|
| 最终正常回答覆盖 | 6/47 | 6/47 | 13/37 | 10/37 |
| 最终空上下文拒答 | 47/47 | 47/47 | 37/37 | 37/37 |
| 最终拒答 precision | 53.41% | 53.41% | 60.66% | 57.81% |
| 原始 token F1 | 0.4643 | 0.4737 | 0.3446 | 0.3575 |
| 最终 token F1，全体正常题 | 0.0673 | 0.0624 | 0.1430 | 0.1314 |
| 正常上下文原始有效引用 ID | 104/104 | 97/98 | 92/92 | 82/82 |
| 空上下文出现无效引用的题数 | 40/47 | 38/47 | 28/37 | 25/37 |

空上下文拒答是合成控制，不是现实拒答准确率；最终拒答主要由校验保证，原始模型仍会编造事实/来源，且有先答后拒的混合输出。自动原始拒答计数只是措辞启发式。

正常题按“原始发布方答案存在”标为可回答，并不意味着每次实际检索上下文都充分。因此正常题拒答不全是误拒；表中拒答 precision 是这一固定对照设计下的描述量，不是逐条专家判定上下文充分性后的真实误拒率。

数字诊断只是答案所有字面数字是否出现在整段参考答案中：dev 原始 **8/16→7/14**，test 原始均 **2/5**；最终仅 dev 各 1 题、test 各 1 题有数字，分母太小，不能解释成数值推理准确率。它也不核实单位、目标量或正确操作数。F1 是词面一致度，不是语义正确率；SOURCE 字段从 raw/served 两者一致移除，避免内联引用和 ID 污染内容与数字指标。修正前摘要保留本地，选择锁不改写。

[非盲诊断](../reports/source_holdout_v1/diagnosis.json)区分了真实错误、解析和过严校验：

- 33/47 dev baseline 拒答由特定问题词检查触发。其中 5 例只缺问句框架词，但其余不能全部当误拦。
- 一例第三方“找不到投保人”被宽泛的不能查找规则误判为模型拒答；一例欧元区间未被美元/百分比数字规则识别。没有为增加覆盖而放宽校验。
- 候选最终答案将 **US Medicare Part B** 混入爱尔兰 HIA 的门诊回答；有效引用 ID 和数字匹配均不能证明整段语义受支持。
- 对 12 个 dev 最终答案直接比较引用与发布方参考后，还发现折扣频率夸大、法律条件/地域限定省略等问题。检查由同一代理非盲完成，没有独立专家语义准确率。

同样的 47 个空上下文提示、同一 seed 下，两臂只有 13 个原始输出字节相同；固定参数不等于 GPU 服务逐字确定性。单次生成的小幅 F1 差异不能直接归因于检索变化。

单卡 RTX 4070 Laptop 8 GiB；观测整卡峰值约 **4,980 MiB**（含桌面/服务占用，不是模型独占分配）；test 输出速度中位数约 **72 token/s**，生成 P95 **2.087/1.991 秒**。文本推理，没有新视觉质量或 QLoRA 训练成果。
